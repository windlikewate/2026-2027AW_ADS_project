# 复杂度图说明

运行 `python src/plot_complexity.py`，依赖 `numpy`、`matplotlib`。默认读取项目的 `output/results.csv` 和对应的 `data/*.in`，不依赖启动目录，不修改原始 CSV。

- `runtime_by_n.png`：六种输入分布的实测耗时，双对数坐标。点为两个种子的平均耗时；误差棒为各个种子及其计时重复中的最小值到最大值，不是置信区间。
- `complexity_fit.png`：各分布分别拟合 `T = a*N*log2(N) + b*K*log2(N) + c`，系数非负。展示实测值、拟合值和在原始毫秒尺度计算的 R²。拟合与评价使用同一批数据，因此 R² 只是描述性指标。
- `complexity_normalized.png`：左图是不经过拟合的 `T/((N+K)*log2(N))`，右图展示实际 K。若归一化比值在较大规模逐渐稳定，可支持该数量级的经验趋势；比值不恒定也不等于推翻大 O 上界。
- `complexity_data.csv`：每条数据的 N、购买总数、K、理论工作量、拟合耗时、归一化耗时。
- `complexity_fit.csv`：各分布的拟合系数和 R²。

## K 的含义

K 是使用优惠券的购买次数，即实际执行取堆顶购买的循环次数。原价购买通过一次除法完成，不能把 CSV 的 `items` 直接作为 K。当前 testbench 在求解器内直接计数，每次调用归零，成功提取堆顶后加一；预热和每次计时重复都校验 K，并把单次运行的 K 写入 `results.csv` 的 `k` 列。绘图优先使用这一列。

设最低原价为 B，统计所有满足 `price[i]-coupon[j] < B` 的商品与优惠券组合数 M。程序先按实际价格从低到高购买这些组合，然后才可能批量原价购买，所以 `K=min(items,M)`。testbench 的独立参考算法通过排序和双指针统计 M，用来核对实际计数；旧版 CSV 缺少 `k` 时，绘图脚本通过排序与二分统计 M 以恢复 K。这些方法均不枚举 N² 个组合。该结论依赖当前求解器以及输入保证所有优惠后价格为正。

## 可用于报告的结论

当前数据覆盖十三个 N、每组两个种子；排除了两个仅用于正确性检查的样例。`unaffordable` 的 K=0，适合观察初始化和排序成本；其他分布用于观察增加购买操作后的总耗时。具体拟合效果以当前图片和 `complexity_fit.csv` 为准。

不能将这些图表述为严格证明或所有输入下的紧确界：每组单独拟合只有二十六个样本，且毫秒尺度的最小二乘偏重较大耗时；小输入计时波动、重复键、堆操作提前停止、缓存等会造成偏差。应保留并解释拟合偏差。

理论上，N 次堆插入的上界为 O(N log N)，K 次购买中的堆操作上界为 O(K log N)，加上排序的平均 O(N log N)，得到平均分析下的 O(N log N + K log N)。当前自定义快速排序没有最坏 O(N log N) 保证，因此不应据此宣称整个实现具有该最坏时间界。三路划分和堆中大量相等键还可能使实际耗时低于这一上界。
